The azaadi project is organized as a pnpm-powered monorepo orchestrated by Turborepo. The workspace is declared in `pnpm-workspace.yaml`, which enumerates the package globs (typically `apps/*` and `packages/*`) that pnpm treats as first-class members of a single dependency graph. Because pnpm uses a content-addressable store and hard-linked `node_modules`, every workspace package shares a single, deduplicated dependency tree, which keeps installs fast and disk usage low even as the number of packages grows. The root `package.json` acts as the orchestration entrypoint: it declares shared devDependencies (Turborepo, TypeScript, linters), defines the top-level task scripts (`build`, `dev`, `lint`, `test`), and marks itself `private: true` so it is never accidentally published.

Turborepo (`turbo.json`) is the task runner that sits on top of the pnpm workspace. It reads the pipeline definition to understand how tasks like `build`, `test`, and `lint` relate to one another, then executes them across all packages in the correct topological order while maximizing parallelism. Its content-based hashing and remote/local caching mean that a package whose inputs have not changed is skipped entirely on subsequent runs, so a full monorepo build after a small change touches only the affected packages and their dependents. Tasks declare their `dependsOn` relationships (for example, `build` depends on `^build`, meaning "build all internal dependencies first") and their `outputs`, which tells Turbo what artifacts to cache and restore.

Together these three files form the backbone of build and orchestration in azaadi. Developers run a single command from the repository root, and Turborepo fans the work out across the workspace, respects the dependency graph, caches results, and aggregates logs. This gives the ergonomics of a single unified build while preserving the modularity of independently versioned packages, and it scales cleanly in CI where unchanged packages are restored from cache rather than rebuilt.
